# ADR 0035: Provenance by repository-batch reconstruction

Status: **Accepted** (2026-10-19) — agent-authored 2026-10-17; the owner signed the ADR on 2026-10-19 ("accept", recorded at their in-session direction)
Date: 2026-10-17

## Context

`AGENTS.md` (Research discipline) requires that language content carry
source URL/title/license/access-date provenance, and `languages/ja-JP/sources.jsonl`
shows the working convention: one `source-entry` row per source, with
`license`, `access.mode` and `use` blocks, plus honest review-pending notes
when the content is an AI-drafted original (rows `ai-drafted-kana`,
`ai-drafted-extension`).

The ru-RU reference pack does not follow it for its bulk content. Between
the 0.4.0 tag (`70ec6830611ef67a2e54b0305c09f38b58798de6`) and the published
0.4.1 tree (`20f994df05478f92b9d2399bbf655066e21ffda6`), 847 lines of ru
content landed (measured by `git diff --numstat` over that range restricted
to `languages/ru-RU/`, recorded in
`state/evidence/OWNER-CHECKLIST-2026-10-16/git-ru-040-to-041-numstat.txt`
and re-confirmed against the tree by file line counts: curriculum goals and
units 810–818, `grammar/concepts.jsonl`, `sentences/journeys-2026-10-14.jsonl`,
`media/manifest.jsonl` bake rows, `world/environments.jsonl`, the review
worklist and the version bump). During that range **zero** rows were added
to `languages/ru-RU/sources.jsonl` or `licenses.jsonl`
(`state/evidence/OWNER-CHECKLIST-2026-10-16.md` §5b). The content itself is
honest about being AI-drafted (`status: "draft"` + `generation` blocks on
every item), but the pack-level provenance ledger stayed at two rows.

Options on the table: cite an external dictionary as the source; leave the
pack unattributed; delete the content; or reconstruct the provenance from
repository history.

## Decision

Reconstruct provenance as an authored-in-repo batch row keyed by the commit
range. `languages/ru-RU/sources.jsonl` gains one `source-entry` row,
`ru-batch-70ec683-20f994d`, whose title names the exact commits
(`70ec683..20f994d`), the added-line count (847) and the files it covers;
whose `access.notes` state that the content was written inside this
repository during that range with no external corpus fetched, copied or
mirrored; whose license is `CC0-1.0` — the license the repo can actually
back for its own authored content per
`languages/ru-RU/licenses.jsonl` (`lic-ru-original`) and the manifest
`content_license`; and whose `use.notes` mark the batch review-pending
(every item `status: draft`, blocker BLK-REVIEW-CAPACITY in
`languages/ru-RU/review/REVIEW_POLICY.yaml`). This is implemented in the
0.4.2 pack update; evidence in `state/evidence/RU-042/`.

The drafting method (AI-drafted, human review pending) is recorded in the
row itself. The commit range is the primary key because the repository
history, not any upstream document, is the observable origin.

## Consequences

- Provenance attests repository history, not upstream derivation. A reader
  learns where the content came from (this repo, this range, AI drafting)
  and nothing more — which is exactly what is known.
- The rows are explicitly review-pending and must not be read as
  human-verified; they do not satisfy REVIEW-001 and change no status,
  maturity (`experimental`) or catalog `review_status`.
- A later human pass may replace the batch row with finer-grained records
  (per-batch worklists already exist in `review/`); the schema's `retrieved`
  and note fields keep the reconstruction date visible.
- `catalog/packs.json` is regenerated by the owner via
  `scripts/build-catalog.sh`; it will pick the new rows up only at the next
  owner-gated rebuild.
- Verification: `validate/lint/test languages/ru-RU`, `cargo test -p
  lts-langpack`, and the CI audits (`audit_content_templates.py`,
  `audit_learner_copy.py`, `validate_handoff.py
  --require-explicit-ledger-records`) all run over the changed pack;
  outputs in `state/evidence/RU-042/verification.md`.

## Alternatives considered

- **Cite an external dictionary as the source.** Rejected: the content was
  not copied from one. Stress spot-checks against the Zaliznyak checkout
  are already recorded as a `reference-only` row (`zalizniak-2010`);
  presenting derived-check provenance as derivation would be a false
  citation and would also import a CC-BY-NC obligation the content does not
  carry.
- **Leave the pack unattributed.** Rejected: violates the research
  discipline in `AGENTS.md` and the pack-schema intent
  (`source-entry.schema.json`); a shipped release with an empty ledger is
  unauditable.
- **Delete the content.** Rejected: disproportionate — the content carries
  honest draft/generation provenance and passes structural gates; the
  ledger gap, not the content, is the defect.

## Status

Proposed. Acceptance is an owner act; this ADR does not self-certify the
reconstruction as reviewed.
