# ADR 0016: Pack-shipped model-output audio for the listening modality

Status: Accepted (owner decision 2026-10-07)
Date: 2026-10-07

## Context

The 2026-10-07 N5/level audit found the ja-JP reference pack ships **zero audio
assets**, so the listening modality has nothing trainable behind it (N5 listening
is 60 of 180 points). The media-first convention already exists: sentences resolve
`media/<id>.wav` and contrast items `media/<id>-<item-index>.wav` before any
synthesis fallback (`schemas/v0.2/sentence.schema.json`,
`phonology-contrast.schema.json`, `crates/langpack/src/layout.rs:100-115`), and
the app already labels audio provenance as `licensed-recording` vs `model-output`
(`apps/desktop/src/practice.tsx:134`, `speech_audio_at` in the desktop crate).
`TTS-001`/`TTS-002` ship the offline Kokoro synthesis chain, and `ADR-0009` scopes
its `espeak-ng-data` GPL-3.0 obligations to the optional payload.

`ADR-0013` separately established, by measurement, that available TTS cannot
realize a Japanese long-vowel contrast (Kokoro v1_0 1.04, v1_1 1.05, OpenJTalk
1.07 for おばさん/おばあさん). So synthesis quality is *not* a single question:
it is adequate for comprehension input and inadequate as a contrast anchor.

Owner decision 2026-10-07: allow TTS model-output audio in shipped packs,
provenance-labeled.

## Decision

1. Pack audio is **generated, not hand-collected**: `scripts/generate-pack-audio.py`
   synthesizes every sentence record and every phonology contrast item
   (`media/<sentence-id>.wav`, `media/<contrast-id>-<item-index>.wav`) with the
   pinned sherpa-onnx runtime + Kokoro export — the same pair the app already
   resolves for on-demand synthesis. Synthesis input is the pack's kana
   `reading` when it declares one, because Kokoro's kanji handling is unverified;
   the written `text` is what the manifest records.
2. **Binaries stay out of git; identity does.** The generated `.wav` files are
   gitignored; the committed `languages/<pack>/media/manifest.jsonl` carries one
   line per asset — id, file, sha256, bytes, sample rate, channels, seconds,
   `provenance`, the synthesizer identity (runtime, model, model sha256, voice,
   speed), `text`, generation date. Each line validates against the new
   `media-asset` schema, so provenance is checked content, not a comment. A
   release build regenerates any missing audio before
   `scripts/build-catalog.sh` packs the `.lpk`, so the manifest and the archive
   always describe the same bytes, and `langpack build` hashes the archive
   afterwards. **Synthesis is not byte-reproducible** — measured 2026-10-07: five
   runs of the pinned chain on one utterance gave five distinct sha256 values,
   including with `--num-threads=1`. The manifest therefore records the identity
   of the bytes that actually shipped; it never promises that a rebuild
   reproduces them, and a regeneration that changes bytes is a pack change
   (version bump + fresh bindings), not a no-op.
3. **Provenance and license records accompany it**: a `licenses.jsonl` and a
   `sources.jsonl` entry naming the synthesis chain, stating the audio is model
   output generated by this project rather than a third-party recording, and
   carrying the ADR-0009 payload scoping for `espeak-ng-data`.
4. **Scope limit — this audio is comprehension input, never a pronunciation
   reference.** `ADR-0013`'s `reference-contrast-weak` abstention and the
   pack-declared numeric production targets stay in force; production scoring must
   not anchor on generated audio it cannot trust.
5. **Provenance is read, not guessed.** `speech_audio_at` and
   `contrast_audio_at` used to label *any* file present in `media/` as
   `licensed-recording`. They now consult `media/manifest.jsonl`
   (`declared_media_provenance`), so shipped generated audio surfaces in the UI
   as model output; packs with no manifest record keep the curated-recording
   default (`ja-demo` is unaffected). Nothing about generated audio implies human
   review — see ADR-0014.

## Consequences

- The listening modality gets real content, offline, with zero third-party
  licensing exposure and no recording effort.
- What is verifiable: the manifest hashes match the bytes in the archive that
  was built with them, so an installed pack can be checked against its own
  manifest, and the synthesis chain is pinned to an exact model export. What is
  **not** verifiable across builds is byte equality of regenerated audio (the
  chain is not deterministic, see Decision 2).
- Enforcement (same day as the first generation run): `media/manifest.jsonl` is
  parsed as validated data rather than swept up as an opaque `media/` asset,
  `Pack::audit_media` pairs manifest rows with the directory in both directions,
  and both `validate(Mode::Install)` and `archive::build` refuse drift. Codes:
  `media_row_unusable`, `media_duplicate`, `media_unlisted` (warning — that file
  has no declared provenance, so the app must not label it), `media_hash_mismatch`
  and `media_size_mismatch` (error in every mode). Presence is judged by posture,
  not per row: a pack with **none** of its declared assets on disk is an unbuilt
  source checkout, reported once as `media_unbuilt` (info in scaffold, error at
  install/build, never 693 lines); a pack with **some** of them is partially built
  and every absent asset is a `media_missing` error in every mode, because a
  manifest that describes part of the audio describes the pack falsely. Verified
  on the real pack: flipping one byte of
  `media/ja.contrast.vowel-length.obasan-0.wav` in a copy makes `langpack build`
  exit 1 naming both digests; deleting all 693 `.wav` bytes from a copy turns
  `validate` into one info line, `test` into exactly one error, and `build` into a
  refusal.
- Consequence for CI: a git checkout carries no audio, so install-mode `test`
  cannot run on ja-JP there. CI runs `validate`/`lint` plus the audits for ja-JP
  and keeps install-mode `test` for packs without audio (ru-RU); the full
  install/build gate for ja-JP runs in `scripts/build-catalog.sh`, which
  regenerates the audio first. The pairing logic itself is pinned by
  `crates/langpack/tests/media.rs` inside `cargo test --workspace`.
- Kokoro's Japanese path cannot voice bare kanji (measured 2026-10-07:
  `Ignore OOV '金'` → `Failed to convert '金' to token IDs`, exit 2). Three of the
  14 contrast items therefore had to gain kana `reading` values (金/木, 千/背,
  百/白). That is a content requirement, not a script workaround: the same chain
  voices contrast items inside the app, so an item without a reading is silent
  there too.
- Measured inventory: 693 assets (679 sentence records, 14 contrast items),
  96,511,536 bytes of `.wav`, `ja-JP.lpk` 76,772,565 bytes
  (sha256 `ad5e712c4490ea494fa2e2fd4ab8f4b23b9b661800efecca8fdff0ee39787d4e`)
  against the 850,167-byte published `0.2.0` archive.
- Honest ceiling: synthesis prosody is machine-grade. Any future claim about
  native-like reference audio needs consented human recordings, which is the
  same owner-gated data path SPEECH-007 already documents
  (`benchmarks/speech/datasets/SOURCING.md`).
- Repository size stays flat; a regeneration run is a build step, and the pack
  archive grows by the audio.
- Pack hashes move when audio is added or regenerated. Concretely: the published
  `0.2.0` ja-JP/ru-RU archives (`catalog/packs.json`) predate generated audio, so
  shipping this media is a version bump plus an owner-authorized republish
  (O-05), and any platform report record bound to the old `pack_sha256` stops
  confirming on the new version.

## Alternatives considered

- **Owner-recorded audio only.** Best trust and quality, and it is the
  `licensed-recording` path that remains open; rejected as the *sole* source
  because it is human labor per sentence and blocks the whole modality on one
  person.
- **Third-party audio datasets.** Rejected pending provenance work: the standing
  source matrix has no verified-license Japanese learner/dialogue audio set, and
  unverified sources are blocked for redistribution (`docs/provenance/`).
- **Commit the `.wav` files to git.** Simplest, rejected: binary churn in history
  against `AGENTS.md` hygiene, and it makes regeneration/hash verification
  optional rather than enforced.
- **Ship no audio (status quo).** Keeps the listening modality empty and the N5
  listening gap open; contradicts the owner's approval.
