# K-10 — HVPT / minimal-pair perceptual discrimination training

## What was built

Pack-data-driven perceptual contrast training, end to end:

- **New pack content type** `phonology/contrasts.jsonl` (schema
  `phonology-contrast`, v0.2): id/status/feature_id/items(2–6)/sources;
  items carry text + optional reading/gloss (post-grading only).
  `feature_id` is reference-checked against phonology feature ids.
  Registered in `schema.rs`, `layout.rs` classify, `pack.rs` content
  list + reference collector.
- **New mastery dimension `phonological-discrimination`**
  (`MasteryDimension` + `common.schema.json` masteryDimension enum —
  also fixed the K-04 gap: `orthography-recognition` was missing from
  that enum). Rationale: hearing a contrast must never grant
  `pronunciation-*` (production) credit; prerequisite records scoped to
  production dimensions stay honest.
- **New activity family** `ActivityKind::Discrimination` in
  `classify_type` (names: discriminate, minimal-pair,
  listen-discriminate, hvpt); `dimension_for(Discrimination, Listening)
  => PhonologicalDiscrimination` (before the listening catch-all).
- **Runner** (`contrast_task_build` + `contrast_audio` in lib.rs):
  target member chosen deterministically (`fnv1a(content_id) %
  items.len()`), choices = the whole contrast set (2AFC — written
  forms ARE the answer space), surface hidden while listening, correct
  answer never crosses IPC pre-grading. Audio media-first:
  `media/<contrast-id>-<item-index>.wav` (licensed recordings win) →
  Kokoro TTS labeled `model-output` → honest error. Evidence
  `activity_id` = the contrast id itself (no language literals);
  scheduler row `<id>#phonological-discrimination`; contrasts join the
  new-item stream and plan view.
- **UI**: listening branch reused (audio button + written choices);
  App.tsx selects `contrast_audio` for the modality and suppresses the
  reading reveal. Heading stays "What did you hear?" (audio branch
  default — correct prompt).
- **Pack data**: ja-demo `ja.contrast.demo.vowel-length`
  (おばさん/おばあさん, licensed media copied from the lexicon wavs);
  ja-curriculum-draft vowel-length + gemination pairs bound to the
  researched features (review-needed, ai-assisted). Pitch-accent pairs
  deliberately excluded: TTS cannot control lexical pitch accent, so
  synthesized audio would train a contrast it cannot produce (honesty
  note in the pack data). valid-full gained an `es.contrast.stress.canto`
  line so the type is covered in install mode too.

## Gotchas

- The planner budget truncates the progression stream; the plan-stream
  test needs a large budget (60 min) since ja-demo now carries 5
  lexicon×2 + 16 orth + 1 contrast items.
- practice.tsx's audio branch hardcodes "What did you hear?" — the
  `heading` prop only applies to the surface branch.

## Gates left for humans

- Contrast pair wording/glosses are ai-assisted `review-needed`
  (REVIEW-001).
- HVPT proper (high-variability speaker sets) needs multiple licensed
  recordings per item; the media naming (`<id>-<index>`) supports it,
  but only one voice exists today — the packs declare single-voice
  pairs honestly rather than claiming HVPT variability.
