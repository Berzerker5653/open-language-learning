## Decisions / gotchas
- Unit activity types must come from `classify_type` families; kanji/kana drills
  reach their runners via the new-item stream + content-id dispatch, so kanji units
  use `encounter-read`/`recall` (→ RecallMeaning → kanji_task_build), never
  `orthography-recognition` as an activity type.
- `progression_items` reads only `curriculum/goals.yaml` — goals stay unsharded.
- Id grammar is ASCII-only: kana ids use romaji suffixes (`ji2`/`zu2` for the
  ぢ/づ collisions); kanji ids use romaji readings.
- Lexicon topic `food-drink` keeps the hyphen in ids (`ja.lex.food-drink.gohan`).
