# K-02 — Listening comprehension runner

## What shipped
- `practice_build` accepts `comprehension-listening`; the task carries
  `surface = null` and `reading = null` natively — a visible transcript would
  disqualify the evidence (MASTERY_POLICY `disqualifying_for`).
- `listening_audio` / `listening_audio_at`: media-first resolution
  (`media/<content-id>.wav` from the active pack), else local Kokoro/sherpa
  synthesis labeled `model-output`, else an honest error. Provenance is shown
  in the UI.
- Grading records `comprehension-listening` evidence (activity
  `ja.activity.demo.mc-listen`) and its own per-modality scheduler row
  (`<content-id>#comprehension-listening`).
- New-item stream in `build_plan` emits both `recall-meaning` and
  `comprehension-listening` per unseen entry, deduped per (content, modality),
  so listening is reachable for new profiles.
- UI: listening branch in `practice.tsx` ("What did you hear?", Play,
  provenance label, honest audio error) + App.tsx audio state.

## Language-pack reuse
Audio resolution is pack-driven: any pack can ship `media/<content-id>.wav`
(licensed recordings) and every item gets synthesized fallback. No language
literals in the runner.
