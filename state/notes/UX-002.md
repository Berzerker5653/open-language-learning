# UX-002 — Home, time-budget practice, capability progress UI

Date: 2026-10-03

## Acceptance mapping

1. **Home presents useful next actions without streaks.**
   - `home_state(profile_id)` composes the default 5-minute plan from the
     scheduler-backed planner (`lts_scheduler::plan_session`): every item
     carries a learning reason (`due-review` / `weak-skill` / `progression`).
   - UI (`apps/desktop/src/home.tsx`) renders reason labels + content +
     modality + estimated seconds; empty plans are stated honestly.
   - Test `contains no streak or attendance mechanics` asserts no
     streak/day/attendance/points/heart surface (ADR-0002).

2. **5-minute practice uses scheduler value, not trivial completion.**
   - `build_plan` inputs: due FSRS items from `store.due_items` with live
     retrievability (`FsrsSpike::retrievability` at app clock), weak skills
     from re-derived mastery confidence (< 0.5 threshold), progression from
     pack goals whose hard prerequisites are met and untouched.
   - Rust test `plan_uses_scheduler_values_under_budget`: seeds one overdue
     FSRS row, one weak reading item, and an Independent-recall prerequisite
     that unlocks a progression goal; asserts all three reasons appear,
     `total_seconds <= 300` for the 5-minute budget, and byte-identical
     re-plans (determinism).
   - Budget presets 5/10/20/30 in UI call `practice_plan(profile_id, minutes)`.

3. **Progress shows capability/modality differences.**
   - `progress_summary` re-derives mastery from the append-only evidence log
     per (content, dimension) — never a single collapsed score.
   - Rust test `progress_shows_modality_differences`: reading evidence moves
     comprehension-reading only; production-writing has no row at all.
   - UI `ProgressView` renders per-dimension rows (state, confidence %,
     needs-refresh badge) with the explicit framing "reading does not imply
     speaking".
