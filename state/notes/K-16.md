# K-16 — Kanji instruction (radicals + mnemonics + SRS gating)

## What shipped

Heisig/WaniKani-style character instruction as declarative pack data —
schema, layout, drill runner, and UI — landing evidence only on
EXISTING mastery dimensions.

## Pack format

- New schema `schemas/v0.2/kanji.schema.json`: id, status, character,
  meanings[], readings[], radicals[], optional mnemonic, sources,
  optional `generation` provenance. AI-drafted mnemonics must carry
  generation + non-approved status (ja-demo's 休 mnemonic is
  `review-needed` with `ai-assisted` provenance).
- Layout `kanji/entries.jsonl` (one per line) wired in `layout.rs`
  (+ doc line), schema registered in `schema.rs`, content kind added
  to `pack.rs` id checking and `domain/ids.rs` (`ContentKind::Kanji`,
  id segment `kanji`).

## Engine (`apps/desktop/src-tauri/src/lib.rs`)

- `kanji_entries()` loader; `kanji_task_build()`: character prompt,
  meaning choices (recall-meaning) or reading choices
  (orthography-recognition), deterministic distractors from other
  entries — same construction as the orthography runner.
- `practice_build` dispatches kanji ids by declared pack data (never
  script literals).
- New-item stream extracted into `add_new_item_candidates()` (testable)
  and kanji entries join it for both drills; unseen-only dedupe as
  everywhere.
- `kanji_list(profile_id)`: cards with radicals, mnemonic + review
  status, and per-drill SRS due dates from scheduler rows
  (`<id>#recall-meaning` / `<id>#orthography-recognition`).
- Invariant: kanji reading evidence does NOT establish kana literacy —
  the roll-up only counts the pack's kana chart units (asserted).

## UI (`apps/desktop/src/App.tsx`)

- "Kanji" route: card list (character, due/new), drill view shows the
  character, `radicals.join(" + ")`, mnemonic labelled with its review
  status, then `PracticeRunner` meaning → reading per character.
