# K-05 — Profile picker / resume at launch

## What shipped
- Native `list_profiles` / `resume_profile` commands (testable
  `list_profiles_at`/`resume_profile_at` helpers; unknown ids fail with
  `unknown profile` before the UI commits).
- Launch flow: after `app_mode`, the UI calls `list_profiles` **first**;
  if profiles exist the app opens a "Welcome back" resume step instead
  of the onboarding wizard. Privacy-notice/pack fetch failures can no
  longer strand a returning learner back at the wizard.
- Resume loads `home_state` + `world_state` and enters the app;
  "Create a new profile" drops into the normal onboarding wizard.
- Fixes the FIRST-LESSON known limit: restart no longer re-runs
  onboarding.

## Verification
- Rust test `list_and_resume_profiles_round_trip` (list, resume,
  unknown-id error).
- vitest: resume step renders profile buttons, no stepper, no account
  language (35 tests).
- End-to-end: launched the real app with a fresh `LTS_DATA_DIR`
  (store migrates), seeded a profile row, relaunched — screenshot shows
  the "Welcome back" card with the "Smoke Tester" button
  (`state/evidence/K-05/resume-screen-2026-10-03.png`); smoke handshake
  still passes (`smoke-ok home-rendered`).

## Build gotcha found
`cargo build` does not re-embed changed `apps/desktop/dist` (tauri
codegen caches); after frontend changes use
`cargo clean -p lts-desktop && cargo build -p lts-desktop --features custom-protocol`
or the tauri CLI path in `scripts/smoke-desktop.sh`.
