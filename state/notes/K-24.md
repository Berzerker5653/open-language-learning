# K-24: `langpack new-unit` / `new-lexicon` scaffold subcommands

## What shipped
- `Command::NewUnit` / `Command::NewLexicon` in `crates/langpack-cli/src/main.rs`.
- `new-unit <pack> <id>`: writes `curriculum/units/NNN-<slug>.yaml` where `NNN` =
  max existing NNN prefix + 10 (`Option<u32>`, so an existing `000-` yields `010-`;
  empty dir yields `000-`). Slug = id segments after the `unit` kind, joined by `-`.
  `goal_id` is auto-picked: first goal id from `curriculum/goals.yaml`, falling back
  to the first id across `curriculum/goals/*.yaml` shards; if none, placeholder
  `<locale>.goal.replace-me`. Activity id derived as `<locale>.activity.<rest>-encounter`.
- `new-lexicon <pack> <id>`: appends one draft JSONL line (status `draft`,
  `REPLACE` placeholders for form/reading/gloss, `REPLACE-SOURCE` citation) to
  `lexicon/entries.jsonl`, creating `lexicon/` if absent.
- `parse_id` validates id grammar via `lts_domain::ids` and enforces the kind
  segment (`unit` / `lex`); wrong kind exits 1 with a clear message.
- `first_goal_id` reads goals with `serde_yaml::Value` (no new schema coupling).

## Design decisions
- Scaffolds are schema-valid immediately: placeholders surface as
  `unresolved_reference` WARNINGS (pack.rs `ref_severity` is Warning outside
  Mode::Install), so `validate` passes with 0 errors and warnings point exactly
  at the REPLACE spots. Authors fill them in; install-time validation still errors.
- NNN+10 sequencing leaves room for insertions; collisions are refused, not
  silently overwritten.
