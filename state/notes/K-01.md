# K-01 — Scenario runtime wired into the desktop app

## What shipped
- Native session runtime `apps/desktop/src-tauri/src/scenarios.rs`:
  `scenario_list` / `scenario_start` / `scenario_attempt` / `scenario_support`
  / `scenario_recovery` / `scenario_transfer` / `scenario_finish`. Sessions live
  in a managed `SessionStore` keyed `"<profile>:<scenario>"`.
- Unlock gate: a scenario is enterable only when its goal's hard prerequisites
  are met per derived mastery (`hard_prereqs_met`). Permission-to-enter is not
  mastery (MASTERY_POLICY `access_permission_neq_mastery`).
- Finish records one scored `interaction` evidence event per completed node
  (prompt family falls back to node event id); no scheduler rows — scenario
  nodes are not discrete memory cards.
- UI: `apps/desktop/src/scenario.tsx` (+ `scenario.test.tsx`, 4 tests),
  "Scenarios" route/nav in `App.tsx`.
- Pack data: `languages/ja-demo/activities/scenarios/first-meeting.yaml`
  (goal `ja.goal.demo.greet`, nodes, recovery branch, support ladder 0/3/5,
  one transfer variant) + `scenario` activity in unit `000-greetings.yaml`.

## Language-pack reuse
Everything (graph, intents, recovery, ladder, transfers) is declarative pack
data under `schemas/v0.2/scenario.schema.json`; the engine contains no
ja-JP literals. Any pack shipping a scenario YAML gets this activity.

## Evidence
- Rust test `scenario_locks_until_prereqs_then_records_interaction_evidence`
  (locked → prereqs met → session → evidence events).
- vitest: `apps/desktop/src/scenario.test.tsx` (locked card, node prompt,
  support ladder, finish verdict).
