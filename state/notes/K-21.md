# K-21 — Generation contract fields in the unit schema

## What shipped

docs/03 §12 dynamic-content constraints become machine-checkable
per-unit data: an AI-drafted unit declares its own envelope and the
validator enforces it.

## Schema (`schemas/v0.2/unit.schema.json`)

Optional `generation_contract` object:
- `allowed_vocab[]`, `allowed_grammar[]`, `register[]` — content ids;
- `new_item_budget` (int ≥0), `expected_interpretations[]`,
  `prohibited_ambiguity[]`, `target_proficiency` (CEFR band enum),
  `validation_method` (`exact-match|choice|human-review|model-validated`).
Required when present: allowed_vocab, new_item_budget, validation_method.

## Validator (`crates/langpack/src/pack.rs`)

- Reference resolution: `allowed_vocab`/`allowed_grammar`/`register`
  ids are collected by `RefCollector` → unresolved ids fail like any
  other reference.
- Coverage rule: when a contract is declared, every activity
  `content_refs`/`concept_refs` entry must be inside
  `allowed_vocab ∪ allowed_grammar` — otherwise
  `content_outside_generation_contract` (Error). The unit cannot use
  material outside the envelope it promised.
