# K-34: PLAT-001 Windows/macOS parity — build config only, Linux-tested

## What shipped
- `apps/desktop/src-tauri/tauri.conf.json`: bundle targets extended from
  `["deb","appimage"]` to `["deb","appimage","nsis","msi","app","dmg"]`
  (Windows installer + macOS app/dmg), and the full desktop icon set
  generated via `tauri icon` (`icon.ico`, `icon.icns`, square PNGs;
  mobile outputs pruned — mobile is a separate milestone per docs/13).
- `.github/workflows/ci.yml`: new `platform-compile` job, matrix
  `windows-latest`/`macos-latest`: `pnpm install` + `pnpm build` +
  `cargo check -p lts-desktop --all-targets`. Compile-only by design;
  a comment in the job forbids adding runtime steps without owner scope.
- `docs/13_RELEASE_AND_DISTRIBUTION.md`: "Platform test status (PLAT-001)"
  section — Linux is the only tested platform; Windows/macOS artifacts must
  ship labeled untested (`tested_platforms: ["linux"]` in the catalog,
  implemented by K-35); promotion to "tested" requires a human runtime
  pass (owner gate).

## Explicit non-goals (owner decision 2026-10-03)
- No Windows/macOS runtime testing; no signing/notarization config
  (REL-001 owner gate); no release publishing.

- `state/evidence/K-34/build-config-2026-10-03.txt`: ci.yml parses;

  icon paths); Linux xvfb smoke still `smoke-ok home-rendered`.
- The win/mac compile checks themselves run in CI (cannot run those
