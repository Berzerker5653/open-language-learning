# U04 — dictation refused Russian and hardcoded a Japanese default (owner review 2026-10-14)

**Change (commit e50ac40, engine):** `DictationTarget.reading` is now optional; the sentence pool filters on usable TEXT, not on a kana reading. Rows whose surface and reading normalize equal stay preferred (clean kana comparison); a pack without reading fields (Russian) dictates its own surface, `reading` traveling as null. `dictation_check` was already script-agnostic (pack ASR locale + char-match) and is unchanged.

**Change (commit 5ece9a4, host):** removed the hardcoded `useState("おばあさん")` default; the target arrives from the ACTIVE pack's pool (`reading ?? text`); a failed fetch clears it; recording against an empty target is held with a named message rather than manufactured into a mismatch. `DictationSentence.reading: string | null`.

**Measured:** `cargo test -p lts-desktop --lib -- dictation` → 8 passed, including the new `dictation_target_uses_the_surface_when_a_pack_has_no_readings` on the pinned Russian reference pack (staged as an installed tree — the archive route refuses gitignored audio, same as the placement test). `dictation.test.tsx` → 9 passed incl. the null-reading render case. The RU↔JA dictation legs in `language-switch.journey.tsx` assert the target input holds a Cyrillic sentence under RU and exactly `おばあさん` after the switch, never the other language's line.
