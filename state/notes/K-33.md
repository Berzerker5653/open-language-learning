# K-33: automated accessibility audit (ACC-001 auto portion)

## What shipped
- `apps/desktop/src/a11y.test.tsx`: static-markup accessibility audit run in
  CI via `pnpm test` (vitest). Renders 9 route surfaces (shell, home, progress,
  practice, scenario, pronunciation, pronunciation-feedback, writing,
  onboarding) with `renderToStaticMarkup` and asserts:
  - no positive `tabindex` anywhere (focus order follows DOM order);
  - every `<button>` has an accessible name (aria-label or text content);
  - every `input`/`select`/`textarea` is labeled (aria-label,
    aria-labelledby, or `<label for>`);
  - shell landmarks: skip link `<a href="#main">`, `<main id="main">`,
    `<header>`, `<nav aria-label="Primary">`;
  - exactly one `h1` on top-level routes (home, progress, onboarding);
  - feedback is announced, not color-only: live regions on practice verdict,
    scenario status, pronunciation feedback, writing verdict;
  - audio playback controls exist with text names for both contrast words.
- Palette contrast math against WCAG 2.2 AA (>= 4.5:1) for 17 body-text
  fg/bg pairs, computed from the `:root` custom properties in
  `packages/ui/src/styles.css` (imported via vite `?raw`; `test.css: true`
  added to `apps/desktop/vite.config.ts`).
- CSS invariants: `@media (prefers-reduced-motion: reduce)`,
  `:focus-visible`, and skip-link visible-on-focus rules must exist.

## Palette fix
`--ink-faint` darkened `#776e60` -> `#756c5d`: it failed AA on `--bg`
(4.46:1); now 4.59 on bg / 5.09 on surface. All 17 audited pairs pass;
lowest is ink-faint/bg at 4.59.

## Scope honesty
Per docs/11, automated checks supplement but never establish conformance.
The human screen-reader matrix (NVDA/VoiceOver/Orca) remains owner gate
O-03; keyboard-only walkthrough and screen-reader announcements are not
covered by this audit. axe/jsdom were not added (no jsdom dependency in the
workspace); the audit uses static markup + CSS math instead.
