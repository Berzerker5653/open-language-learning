# K-35: community catalog happy path artifacts

## What shipped
- `langpack catalog` subcommand (crates/langpack-cli): builds/refreshes a
  packs.json from built `.lpk` archives. Entries carry pack_id, version,
  display_name, locale, author, license, review_status (mapped from pack
  maturity; never upgraded), min_sdk_version, url (from `--url-template`,
  https enforced), sha256, size_bytes — the exact contract the app's
  `packs::validate_entry` accepts (apps/desktop/src-tauri/src/packs.rs).
  Upserts by pack_id, sorts, and stamps `tested_platforms: ["linux"]`
  (PLAT-001 honesty: only Linux runtime is tested).
- `archive::read_entry` + public `archive::hex_sha256` in lts-langpack:
  read a single entry (manifest.yaml) from an archive without extraction.
- `scripts/build-catalog.sh`: builds `.lpk` artifacts for the shipped packs
  (languages/ja-JP, ja-demo, eo-demo fixtures) into `dist/preview/` and
  writes a DRAFT catalog to `dist/preview/packs.json` (gitignored).
- `catalog/preview-entries.json`: ja-demo sha/size refreshed to the
  current deterministic build (fixture grew since the old preview entry).

## Governance preserved (not bypassed)
- The live `catalog/packs.json` stays `"packs": []`: its own note and
  docs/packs/CONTRIBUTING.md require `langpack test` + complete licenses
  before an entry is added; ja-JP fails only on LIC-001 gates. Merging
  entries and publishing release assets is owner gate O-05.
- The draft catalog's placeholder URL is explicit; the app enforces
  https + GitHub release hosts at install.

## Clippy cleanup (CI hygiene, same commit)
The repo's CI has never run (unpublished, O-05), so pre-existing
`-D warnings` lints accumulated and would break the `rust` job. Fixed:
needless borrows (pack.rs, lib.rs), let-unit (scenarios.rs),
assert_ne-with-bool (lib test), and two too-many-args APIs refactored to
input structs (`lts_storage::NewMinedItem`, internal `SubmitOpts`).
No behavior change; all callers migrated.
