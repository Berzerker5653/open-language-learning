A second gap, found by checking what ADR-0029 claimed rather than what the code
did (same tree):
  The ADR said listings set direction "per element from each pack's own rtl".
  True for onboarding.tsx (PackText rtl={pack.rtl} locale={pack.locale} at line
  190); false for the installed-pack list in language.tsx, where the InstalledPack
  type already carried rtl (line 21) while the list printed {i.display_name} with
  no direction at all — an ar-MA pack's own name would have rendered mis-ordered
  inside Settings. Fixed: that name now renders through PackText with the pack's

  limit instead of over-claiming coverage.

  (ADR-0029)" — the ar-MA pack renders <span dir="rtl" lang="ar-MA"> next to an eo
  pack rendering <span lang="eo"> with no direction, which is what proves the
  active pack does not decide another pack's name.
