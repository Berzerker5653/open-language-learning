## Protocol (deviations recorded honestly)

- Cold start boundary: BUDGETS says app_end = "first interactive paint (home
  route mounted, input handler attached)". The closest marker the app itself
  emits is the walkthrough's mount-time ack `smoke-ok home` — React mounted
  and native IPC answering. Measured as: fork+exec of the release binary ->
  that line visible in the marker file, polled at ~10 ms (overestimate < frame).
- Cold runs: 5 runs (BUDGETS cold protocol: 3), fresh process and
  fresh throwaway LTS_DATA_DIR per run; page cache NOT flushed (needs root;
  same deviation class as PERF-001 recorded for trials). Percentiles:
  nearest-rank over 5 samples (p95 = max of 5).
- X: one persistent Xvfb (`-screen 0 1280x800x24`) on a dedicated display spans
  all runs so X startup is not billed to per-run exec->home time. The binary
  forces the WebKit DMABUF fallback itself (lib.rs `force_webkit_fallback_renderer`).
- RSS: `/proc/<pid>/status` VmRSS every 2 s during one full smoke walk;
  sampling cannot catch sub-2s spikes; "base" = median of samples,
  peak-delta = max - min. Main-process and process-tree totals both reported.
- No other CPU-heavy processes were started; per-run load average recorded
  below and in metrics.json.

## App-side responsiveness during inference (webview probe, LTS_SMOKE_PERF=1)

Probe windows inside the real walkthrough; inference = three
`pronunciation_check` calls through the installed aligner
(ggml-tiny.bin). Markers verbatim:

```
perf:asr-model:ggml-tiny.bin
perf:rafmax:asr-inference:17
perf:longtasks:asr-inference:0
perf:inp:asr-inference:28
perf:windows:asr-inference:1
perf:rafmax:idle-baseline:17
perf:longtasks:idle-baseline:0
perf:inp:idle-baseline:30
perf:windows:idle-baseline:1
perf:cancel-skipped:no-product-seam
```

Method notes: `perf:rafmax` = worst animation-frame gap in the window (the
webview's main-thread blocking proxy); `perf:inp` = synthetic keydown ->
double-rAF paint, sampled every 300 ms, worst value kept; `perf:longtasks` =
PerformanceObserver long-task entries. `app.cancellation.asr_cancel_effect_ms`
is deliberately NOT measured: the shipped whisper-cli invocation has no
cancel seam, and the app says so (`perf:cancel-skipped:no-product-seam`)
instead of inventing one to measure.
